# Architecture

## Overview

```
┌──────────────────────────────────────────────────────────────┐
│                        rk3568_camera                         │
├──────────┬──────────┬──────────┬───────────┬────────────────┤
│ capture  │ display  │ encoder  │ inference │ fisheye_mesh   │
│ (V4L2)   │ (WL/EGL) │ (MPP)    │ (RKNN)    │ (GLES VBO)     │
├──────────┴──────────┴──────────┴───────────┴────────────────┤
│                     pipeline (threading)                     │
├──────────────────────────────────────────────────────────────┤
│  frame.h: ring buffer (SPSC, depth=1) + frame_t (dma_buf)   │
└──────────────────────────────────────────────────────────────┘
```

## Modules

### capture.c — V4L2 camera capture
- Opens `/dev/videoN` (N = 0..3)
- Sets NV12 format 1920x1080 @25fps
- MMAP buffers + dma_buf export (VIDIOC_EXPBUF)
- `cap_dequeue()` returns `frame_t` with `ptr` (mmap), `fd` (dma_buf), `stride`

### display.c — Wayland/EGL/GLES2 rendering
- Wayland client with xdg-shell
- EGL + OpenGL ES 2.0 context (Mali G52 GPU)
- NV12→RGB via GPU shader (`shader_yuv.h`, copied from factory AVM `texture_y_uv.frag`)
- Three display modes (env-controlled):
  - **GRID** (default): 2×2 quad, 4 vertices per tile, `GL_TRIANGLE_FAN`
  - **FISHEYE_GRID** (`FISHEYE_MODE=1`): 2×2 fisheye mesh, 2401 vertices per tile, `GL_TRIANGLES` VBO
  - **AVM** (`AVM_MODE=1`): sidebar + vehicle placeholder + 4 corrected tiles
- Per-camera UV mesh generated by `fisheye_mesh.c`
- OSD detection overlay via flat-color shader

### encoder.c — MPP hardware encode
- Per-camera encode thread
- H.265 (default) or H.264
- Reads `frame_t` from encoder ring, feeds MPP

### inference.cc — RKNN YOLOv5 inference
- RKNN SDK (librknnrt.so)
- Model: yolov5n_320.rknn (320×320) or yolov5.rknn (640×640)
- Person-only filtering, confidence + NMS
- Optional RGA dma_buf preprocess (`--rga` flag)
- Optional CPU NV12→RGB fallback (via turbojpeg)
- Temporal smoothing (`smooth.h`)

### fisheye_mesh.c — GPU fisheye undistort
- Kannala-Brandt 4-parameter fisheye model
- Per-camera calibration (chessboard, OpenCV fisheye)
- Generates UV mesh + position VBOs for GLES rendering
- Supports rotation/flip per camera (`FISHEYE_ROTATE`, `FISHEYE_FLIPX/Y`)
- Live UV debug: `FISHEYE_DEBUG_CAM=N` + `FISHEYE_LIVE_DUMP=1`

### pipeline.c — Thread coordination
- Capture thread per camera: DQBUF -> ring_put (disp + enc rings)
- Encode thread per camera: ring_get -> MPP encode
- Inference thread: ring_get (deep copy) -> RKNN detect
- Display: main thread reads disp_ring -> disp_update -> disp_draw
- Max 30fps display update

## Data Flow

```
V4L2 DQBUF (mmap ptr)
    │
    ├──> display ring ──> disp_update() ──> import_nv12 (memcpy Y+UV → GL texture)
    │         │
    │         └──> disp_draw() ──> GPU shader (NV12→RGB) ──> eglSwapBuffers
    │
    ├──> encoder ring ──> MPP encode ──> /tmp/cam_N.h264
    │
    └──> [optional] inference ring ──> deep copy NV12 ──> [RGA preprocess] ──> RKNN
```

## Zero-Copy Paths

| Path | Zero-copy? | Method |
|------|-----------|--------|
| V4L2 -> display | No | memcpy Y+UV planes to GL texture (stride strip) |
| V4L2 -> encoder | Yes | MMAP ptr passed via ring buffer |
| V4L2 -> inference (RGA) | Yes | dma_buf fd imported via RGA importbuffer_fd |
| V4L2 -> inference (CPU) | No | Deep copy + CPU NV12->RGB via turbojpeg |

## RGA dma_buf Correct Path

```
importbuffer_fd(fd, size) -> wrapbuffer_handle(width, height, format) -> improcess
```

**Wrong path (avoid):**
```
wrapbuffer_virtualaddr(ptr, size)  ← uses CPU virtual address, not dma_buf
RGA NV12->RGB conversion           ← should be done by GPU shader, not RGA
```

## Factory AVM Technology

The board ships with a factory 360° AVM system at `/oem/birdview/`. Key findings:

- **Method**: GPU mesh/shader inverse mapping (NOT CPU remap, NOT RGA)
- **Data**: `calibinfo.lua` (intrinsic/extrinsic), `lens.lua` (42 lens models, 0.5° lookup table)
- **Mesh**: Runtime-generated Sphere/Circle/Plane via C++ functions in `libLuaApi.so`
- **Render**: `texture_y_uv.frag` shader (reused in our project)
- **Calibration**: Chessboard "PosedMarker" pattern, 8 pattern points per camera
- **Issue**: DistorParam values [13, 35, -2, -4.9] use an unknown polynomial model incompatible with standard OpenCV; must use lens table or re-calibrate

We re-implemented the GPU mesh approach with Kannala-Brandt model + chessboard calibration, achieving 100% per-camera UV coverage.

## Threading Model

```
main:       Wayland dispatch + disp_update + disp_draw + stats
capture[0]: DQBUF -> ring_put(disp+enc) -> QBUF
capture[1]: DQBUF -> ring_put(disp+enc) -> QBUF
capture[2]: DQBUF -> ring_put(disp+enc) -> QBUF
capture[3]: DQBUF -> ring_put(disp+enc) -> QBUF
encoder[0]: ring_get(enc) -> MPP encode
encoder[1]: ring_get(enc) -> MPP encode
encoder[2]: ring_get(enc) -> MPP encode
encoder[3]: ring_get(enc) -> MPP encode
inference:  ring_get(infer) [deep copy] -> [RGA preprocess] -> RKNN detect
```
